# client-demo-public-qa

Generated by **qaff** (QA Framework Factory) from blueprint
`java-maven-selenium-junit5-allure`.

## What was generated

A Maven multi-module Java QA framework:

```
client-demo-public-qa/
├── pom.xml
├── qa-factory.lock.json
├── framework-core/                # shared utilities (config, resources)
├── framework-web-playwright/      # Playwright (Java) session factory + base page/test
├── framework-mobile/               # Appium driver factory and base mobile test
├── framework-performance/         # baseline + reports + provider placeholders
├── apps/demo-shop/web-desktop/    # smoke test against a local HTML fixture (Playwright engine)
├── apps/demo-shop/ios/            # iOS native Appium smoke (XCUITest)
├── apps/demo-shop/api/            # RestAssured API smoke (Quality Impact Pack)
```

## Prerequisites

- **Java 21** recommended (the generated POM is configured with
  `<maven.compiler.release>21</maven.compiler.release>`).
- **Java 17** is supported as a compatibility target — re-generate with
  `qaff create --config ... --output ... --java 17` (Phase 1).
- **Maven 3.9** or newer.
- **Chrome or Chromium** installed locally. Selenium 4 ships with Selenium
  Manager which downloads a matching `chromedriver` automatically the first
  time tests run; this requires network access on the very first run only.
  If your browser binary is not on `PATH` as `google-chrome`, set
  `BROWSER_BINARY=/usr/bin/chromium` (or similar) before running tests.
- Apps with `web.engine: playwright` use **Playwright for Java** — the
  bundled browsers download automatically on the first test run (network
  required once). Set `PLAYWRIGHT_BROWSERS_PATH` to relocate that cache, or
  `BROWSER_BINARY=/usr/bin/chromium` to run a system-installed chromium
  instead of the bundled one.

## How to run

```bash
mvn verify
```

This compiles every module and executes the Selenium JUnit 5 smoke test in
each `apps/<id>/web-desktop`. Each test opens a deterministic local HTML
fixture (no public website, no SauceDemo, no network beyond Selenium Manager
bootstrap) and asserts the page renders.

### Allure results

After `mvn verify` you will find raw Allure results under each app:

- `apps/demo-shop/web-desktop/target/allure-results/`

Render the report with the [Allure CLI](https://allurereport.org/):

```bash
allure serve apps/demo-shop/web-desktop/target/allure-results
```

## Local fixture

Each app ships with its own static HTML fixture under its test resources:

- `apps/demo-shop/web-desktop/src/test/resources/fixtures/demo-shop.html`

Fixtures are loaded via the JVM classloader and opened with a `file://`
URL, so tests are fully offline and deterministic. See
[`docs/local-fixture.md`](docs/local-fixture.md) for details. To run the tests
against your own application instead, see
[`docs/HOW_TO_TARGET_YOUR_APP.md`](docs/HOW_TO_TARGET_YOUR_APP.md).

### External web targets

`mvn verify` runs the web smoke of these apps against the configured URL, so it fails
until that URL is reachable — replace a placeholder such as `https://example.invalid`
first:

- `demo-shop` → `https://www.saucedemo.com/`

`qaff doctor --project .` reports whether each target answers. To run the same smoke
against the bundled fixture instead: `QAFF_WEB_TARGET=fixture mvn verify`
(see [`docs/HOW_TO_TARGET_YOUR_APP.md`](docs/HOW_TO_TARGET_YOUR_APP.md)).

## Module dependency direction

```
apps/*  ──►  framework-web-playwright  ──►  framework-core
```

- `framework-core` must **not** depend on `framework-web-playwright` or `apps/*`.
- `framework-web-playwright` must **not** depend on `apps/*`.
- `apps/*` may depend on `framework-web-playwright` and `framework-core`.
- `apps/<a>` must **not** depend on `apps/<b>`.

The generator runs a post-generation validator that asserts these rules
against the actual POMs and fails generation if any rule is violated.
`mvn validate` / `mvn verify` enforce the same rule on every build through
`maven-enforcer-plugin` (execution `enforce-dependency-direction` in the root
POM), so a hand-edited POM that breaks it fails the Maven build.

## Helper scripts

Cross-platform scripts for local verification live in `scripts/`:

| Script | What it does |
| --- | --- |
| `verify-framework` | Runs `mvn -B verify` and prints a short summary |
| `run-all-tests` | Runs `mvn -B verify` across all modules |
| `run-web-smoke` | Runs web-desktop smoke tests per app |
| `run-web-mobile-smoke` | Runs web smoke tests under Chrome mobile-device emulation for apps with the `web-mobile` layer |
| `run-mobile-appium-smoke` | Runs Appium mobile smoke tests for apps with the `mobile-appium` layer |
| `run-api-smoke` | Runs API smoke tests for apps that include the `api` layer |
| `run-integration-smoke` | Runs integration smoke tests for apps that include the `integration` layer |
| `run-performance-smoke` | Validates performance module scaffolding per app (Quality Impact Pack only) |
| `run-gatling-smoke` | Runs local/offline Gatling Java reference smoke per performance app (opt-in) |
| `run-k6-import-smoke` | Imports optional k6 summary files into `framework-performance/reports/<app>.result.json` |
| `run-jmeter-import-smoke` | Imports optional JMeter JTL files into `framework-performance/reports/<app>.result.json` |

Windows: `.\scripts\verify-framework.ps1`  
Linux/macOS: `bash scripts/verify-framework.sh`

`run-performance-smoke` keeps validating module scaffolding only.
`run-gatling-smoke` is explicit opt-in provider smoke. Default
`mvn verify` does not run Gatling. Scope: local provider reference smoke
only; not a load test, benchmark, trend analysis or regression gate.
`run-k6-import-smoke` and `run-jmeter-import-smoke` are optional import
helpers for existing provider outputs. They do not execute provider workloads.

See [`docs/local-scripts.md`](docs/local-scripts.md) for details.
